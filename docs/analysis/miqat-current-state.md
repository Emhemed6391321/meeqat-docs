# الحالة الراهنة لمنظومة «ميقات» (مستودع Meeqat1.1)

> **المصدر:** فحص القراءة فقط للشيفرة المحلية `Meeqat1.1` (آخر التزام: `Auto deploy 2026-10-10 14:59`)، وتقرير «المراحل المنجزة» (5/4/2026).
> **حدود:** لم أصل إلى الخادم المنشور، لذا كل ما يلي عن **الشيفرة** لا عن **النسخة المنشورة**. التحقق من النشر مطلوب (انظر §6).
> **مفتاح:** ✅ مثبت في الشيفرة · ◐ جزئي · ✖ غير موجود · ؟ غير قابل للتحقق.

## 1. البنية
React 19 + TypeScript + Vite (واجهة)، Node/Express + TypeScript (خادم)، MySQL 8 (mysql2)، Docker/Dokploy أو cPanel Passenger، نسخ احتياطي يومي مشفر AES-256 عبر Telegram، إشعارات أخطاء Telegram، ترحيلات SQL تلقائية (≈25 ملفًا).
**ملاحظة:** وثيقة المراحل (أبريل) تذكر 9 مراحل؛ الشيفرة الآن أوسع (Meeqat 1.2: مخيمات، حافلات، طبي/SOS، أمتعة، محفظة) ولم تُوثَّق.

## 3. الأمن والحوكمة — **ملاحظات حرجة** (من الشيفرة)

| # | الملاحظة | الدليل | الأثر |
|---|---|---|---|
| S1 | **لا مصادقة فعلية على الـAPI.** دالتا `authenticateUser`/`requireRoles`/`authorizePilgrimAccess` معرّفتان في `authMiddleware.ts` لكن **غير مستخدمتين في أي مسار**. | استدعاؤها 0 مرة في `routes/*` | أي شخص يعرف عنوان الخادم يقرأ/يعدّل/يحذف بيانات الحجاج والمستخدمين |
| S2 | تسجيل الدخول يعيد كائن المستخدم **بلا رمز (token/JWT)**؛ والتحقق من الدور والمجموعة يتم في **الواجهة فقط** (`App.tsx`). | `userRoutes.ts` /login | تقييد المشرف بمجموعته شكلي |
| S3 | مسارات خطرة مكشوفة: `DELETE /pilgrims/delete-all`، `POST /backup/restore`، `GET /backup/download/:file`، `GET /users` | `pilgrimRoutes`, `backupRoutes`, `userRoutes` | فقدان/تسريب كامل |
| S4 | **Webhook تحديث** `POST /api/system/update` يشغّل `git pull && npm run build` برمز **مكتوب صراحةً في الشيفرة**. | `server.ts` | تنفيذ أوامر على الخادم إذا تسرّب الرمز |
| S5 | `/api/test-db` يكشف اسم المستخدم والمضيف وعدد الجداول وطول كلمة المرور بلا حماية. | `server.ts` | إفصاح معلومات |
| S6 | `cors()` مفتوح، وحجم الجسم 50MB. | `server.ts` | |
| S7 | كلمات مرور قديمة قد تكون نصًا صريحًا (تُرقّى لـbcrypt عند أول دخول)؛ ترحيل لتغيير كلمة مرور مستخدم بعينه. | `userRoutes.ts`, migration `…_update_shebane_password` | |
| S8 | **بيانات حقيقية في Git:** ملفات نسخ احتياطي `.sql` بأحجام ≈0.7–0.9MB و`HAJ.CSV` و`dist.zip` مُتتبَّعة في المستودع (`origin: github.com/Emhemed6391321/Meeqat1.1`). خصوصية المستودع **غير متحقق منها**. | `git ls-files` | تسريب بيانات حجاج إن كان عامًا |

> ملاحظة: S1–S10 مستنتجة من الشيفرة المحلية. إن كانت النسخة المنشورة تضع طبقة حماية أمام التطبيق (Traefik basic-auth، IP allowlist) فقد تخف الشدة، ولا أستطيع التحقق.

## 5. الجودة وقابلية الصيانة
- ملفات واجهة ضخمة: `GroupManager.tsx` (186KB)، `HousingManager.tsx` (153KB)، `AdminTools.tsx` (115KB)، `PublicPilgrimForm.tsx` (113KB)، `PilgrimList.tsx` (107KB). صعوبة اختبار وصيانة.
- جذر المشروع مزدحم بسكربتات إصلاح لمرة واحدة (`fix_*.py`, `perfect_fix.py`, `tmp.txt`, `temp_modals.txt`) وبـ`dist.zip` وكتل `.zip` كبيرة.
- مجلد `reports/` نسخة قديمة من التطبيق (تكرار).
- `README.md` أصلي من AI Studio ولا يصف المشروع؛ لا CHANGELOG؛ اختبارات آلية: لا شيء مثبت (فقط سكربتات `test_*.ts` يدوية) ؟.
- `.env.local` يحوي `GEMINI_API_KEY=PLACEHOLDER` فقط (لم أطّلع على `backend/.env`).

## 6. ما لم يُتحقق منه
1. ما إذا كانت النسخة المنشورة تطابق آخر التزام، وهل توجد حماية أمام الـAPI.
2. خصوصية مستودع GitHub.
3. التشغيل الفعلي (لم أشغّل التطبيق؛ تحليل ثابت فقط).
4. عمق منطق التسكين والتوزيع التلقائي وقواعد الصحة (لم أقرأ `pilgrimController` و`GroupManager` سطرًا سطرًا).
5. مدى صحة ادعاءات تقرير أبريل (الجداول أعلاه تقدّم أدلة لمعظمها).
